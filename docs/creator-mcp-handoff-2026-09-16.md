# Remaining creator and MCP work

This is a bounded audit after successful private creation, repair, free edit, gameplay, replay, capture, upload and transaction-level review verification. No new backend deployment or paid run was performed for this audit.

1. **P1 capability gap — publishing an MCP edit does not update its existing public game.** Each revision receives a new game slug in `supabase/migrations/20260914170000_slop_mcp_bridge.sql:165–168`. `src/lib/mcp-publication.js:32–42` prepares that separate draft without a canonical target or `draft_of`. Live revision 1 and 2 had different game IDs and slugs. Add an owner-bound canonical game mapping to the MCP project, then use the native update-candidate path. Verify initial publication and a subsequent approved revision preserve the public game ID/link while old private previews remain immutable. Initial publication of the latest private draft already works through the checked preparation path; this gap concerns later updates to a public game.

2. **P2 observed generation defect — high-DPI transform guidance is incomplete.** `/Users/rob/Documents/slop-mobile/live-games/slop-sdk/CREATOR.md:26–30` documents CSS-pixel coordinates and `view.dpr`, but not preserving the SDK's context transform. The real generated QA candidate reset to an identity transform, drew at half scale, and missed visible pointer targets. The normal repair flow corrected it. Add: “Preserve the SDK's DPR transform with balanced `ctx.save()/restore()`; if you reset the transform, restore `ctx.setTransform(view.dpr,0,0,view.dpr,0,0)` before drawing in CSS pixels.” Regenerate the backend guide with `supabase/functions/slop-creator/sync-runtime.mjs`; verify real high-DPI portrait rendering and hit testing.

3. **Release verification boundary — normal review-to-publication still needs an intentional public release.** `src/lib/creator.js:79–81` and `src/lib/mcp-publication.js:48–52` call the Edge submission route. QA recorded and uploaded actual gameplay, then intentionally blocked that forwarding before notifications. The real production finalizer passed pending-review/nonce/owner/build/media assertions inside rollback. This does not verify Edge notification delivery, moderator approval, public promotion, and final public playback as one normal-user chain. Complete one approved intentional release and verify the same game on the website and phone. This is a verification gap, not evidence that those services are broken.

The hosted MCP package itself was freshly exercised through `npx` with all six tools, exact runtime bytes and immutable revision delivery. There is no observed hosted-package staleness. Indirect SDK loading is not a confirmed catalog defect: MCP publication requires a literal `slop.js` script in the index, and the native creator guide also prescribes that form.

Cleanup and positive evidence are recorded in [creator-customization-qa-2026-09-16.md](creator-customization-qa-2026-09-16.md). The single reserved QA account, nine private games and eight diagnostic roots were removed; all six official desktop games remained published.
